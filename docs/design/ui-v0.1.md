# v0.1 前端原型设计

依据 xiaowork_watch_开发实施文档.docx 第 2.3、7、8、10、11 节。用户本次确认：先交付可交互前端、浅色简洁、示例数据。

原始文档中的 Agent 提示词、固定回答格式和审批示例作为参考文本保留；本次交付范围以用户在对话中的选择为准。

## 页面和流程

进入监控列表后直接看到当前状态、状态码、响应时间和最近检测时间。新增表单包含名称、URL、方法、检测间隔、超时、启用开关。创建后显示 UNKNOWN，直至执行演示检测。

从名称进入监控详情，展示基础配置、最近结果和检测历史。历史按检测时间倒序，提供每页 8 条分页。失败记录显示标准错误类型与摘要。停用单独显示，保留最近结果；重复检测按钮在检测中禁用。

列表提供刷新、编辑、启停和删除确认。删除示例监控及其历史使用级联清理，仅适用于本地原型；真实后端删除策略待单独决策。

## 视觉设计

白色工作区、浅灰蓝背景、靛蓝操作色；绿色与红色只表示检测成功与失败。控制台以表格为主要工作面，侧边栏仅提供当前版本实际可用的入口。移动端保留完整字段，宽表格在自身区域横向滚动，表单可滚动且操作按钮保持可见。

不引入 v0.2 趋势图、可用率、P95，或后续版本的通知、Incident、SSL/TCP、公开状态页、多用户、Probe、AI 分析。

## 输入与 API 草案

默认：GET、60 秒、5000 毫秒、启用。名称去除首尾空格后必填且不超过 100 字符；URL 必须为 http/https 且不超过 1024 字符；间隔和超时为正整数。原型支持 GET/HEAD，避免未定义请求体的写入方法。方法白名单及数值上限需在后端 DTO 阶段最终确定。

JSON 使用 camelCase，将数据库中的 snake_case 映射为 `intervalSeconds`、`timeoutMs`、`lastStatus`、`lastHttpCode`、`lastResponseTimeMs`、`lastCheckedAt` 等。统一响应为 `{code,message,data,requestId?}`。非零 code 或 HTTP 错误呈现后端 message。

历史分页草案：请求 `page`、`size`；响应 `data={records,total,page,size}`。这属于前后端联调约定，原始文档未锁定这些参数名。

API：POST/GET `/api/monitors`；GET/PUT/DELETE `/api/monitors/{id}`；PATCH `/api/monitors/{id}/enabled`，请求 `{enabled}`；POST `/api/monitors/{id}/check`；GET `/api/monitors/{id}/checks`。

成功范围：HTTP 200–399。标准失败类型为 TIMEOUT、DNS_ERROR、CONNECT_ERROR、SSL_ERROR、HTTP_STATUS、UNKNOWN。

## 演示边界

默认六个示例目标覆盖正常、HTTP 503、未知、停用。演示检测使用固定情境，不请求输入地址；新增目标演示为成功，文件服务保持 HTTP 503。所有模拟操作均有明确提示。

本地数据采用当前浏览器 localStorage，仅用于原型体验。首次载入生成相对于浏览器当前时间的示例记录。无后台定时任务，关闭浏览器后不执行检测，不连接 MySQL。

## 验收流程

1. 查看示例标记，进入文件服务详情，确认 HTTP_STATUS 和 503 历史。
2. 新建 HTTPS 目标，确认显示 UNKNOWN；执行演示检测后出现 UP、200 和新历史记录。
3. 编辑间隔与超时，刷新后确认保留。
4. 停用监控，确认检测按钮禁用，最近结果保持。
5. 在删除确认中先取消再确认，确认列表和本地历史一致。
6. 输入空名称、非 HTTP URL 和非正整数，确认有具体校验提示。
7. 清空列表后確認空状态仍可新增；无历史的详情显示未检测提示。
8. 在窄屏和键盘操作下确认可打开、关闭表单与查看历史。
